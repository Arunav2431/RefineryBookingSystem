-- CONTROLLERS/ --
  Controllers/AccountController.cs
    Feature: Authentication
    - Login  -> Windows username + password, two-step auth
                (local Identity first, then CompanyAuthService)
                Auto-provisions user on first company-server login.
                Refreshes FullName + Department on every login.
    - Logout -> Signs out and redirects to login page.
    - AccessDenied -> Shown when user lacks permission.

  Controllers/AdminController.cs
    Feature: Admin Panel
    - Users()                -> List all users; shows hall count badge for Allocators
    - CreateUser()           -> Create Admin, ITFM, or Allocator accounts
                                For Allocator: mandatory hall selection (checklist).
                                Halls are assigned atomically with account creation.
                                (regular User accounts are auto-created on login)
    - ManageAllocatorHalls() -> View/update which halls an Allocator is assigned to.
                                Admin can reassign halls at any time.
    - ChangeRole()           -> Change an existing user's role
    - DeactivateUser()       -> Lock out a user account
    - ReactivateUser()       -> Re-enable a locked account
    - BookingHistory()       -> View all bookings (searchable, paginated)
    - CancelBooking()        -> Force-cancel any active booking

  Controllers/AllocatorController.cs
    Feature: Booking Approval Workflow (HALL-SCOPED)
    Each allocator ONLY sees bookings for halls assigned to them by Admin.
    Admin users bypass scoping and see all halls.
    - Index()    -> Dashboard: pending bookings for ASSIGNED HALLS ONLY.
                   Tab counts (pending/approved/rejected) also scoped.
                   If no halls assigned: shows warning message.
    - Details()  -> Full booking detail. Returns 403 if booking is for
                   a hall not assigned to the current allocator.
    - Approve()  -> Approve booking. 403 if hall not assigned.
    - Reject()   -> Reject booking. 403 if hall not assigned.
    - Export()   -> Excel export scoped to allocated halls only.

  Controllers/BookingController.cs
    Feature: Conference Room Booking (User-facing)
    - Index()    -> My Bookings list for the logged-in user
    - Calendar() -> Visual calendar of room availability by date
    - Create()   -> Booking form: room, date/time, purpose, attendees,
                    IT/AV requirements. Conflict detection included.
    - Cancel()   -> User cancels their own upcoming booking

  Controllers/HallBlockController.cs
    Feature: Hall Blocking (Admin & Allocator)
    - Index()  -> List all active hall blocks
    - Create() -> Block a room for maintenance/event period
    - Delete() -> Remove an existing block

  Controllers/HomeController.cs
    Feature: Landing Page & Help
    - Index()    -> Main dashboard (content adapts per role)
    - Helpdesk() -> IT/support helpdesk information page
    - Privacy()  -> Privacy policy page
    - Error()    -> Generic error display

  Controllers/ITFMController.cs
    Feature: IT & Facilities Management
    - Index()        -> ITFM dashboard: bookings with IT requirements
    - MarkReady()    -> Confirm AV/IT equipment is prepared
    - MarkNotReady() -> Flag equipment issue for a booking


-- MODELS/ --
  Models/ApplicationUser.cs
    Extends Identity IdentityUser with:
      FullName        -> Pulled from company AD/LDAP on login
      Department      -> Pulled from company AD/LDAP on login
      EmployeeBadgeId -> NRL employee badge number
    UserName = Windows domain username (e.g. john.doe)

  Models/Booking.cs
    Core booking entity:
      ConferenceRoomId, UserId (foreign keys)
      StartTime, EndTime
      Purpose, ExpectedAttendees
      Status: Pending / PendingAllocatorReview /
              Approved / Rejected / Cancelled / Completed
      RejectionReason
      HelpDeskTicketNumber
      ITRequirement (linked IT/AV needs)

  Models/ConferenceRoom.cs
    Conference room master data:
      Name, BuildingLocation, Capacity
      HasProjector, HasVideoConferencing, HasWhiteboard
      IsActive (admin can disable a room)

  Models/ITFacilityRequirement.cs
    IT/AV requirements for a booking:
      NeedsLaptop, NeedsProjector, NeedsVideoConferencing
      NeedsMicrophone, NeedsRecording
      SpecialInstructions
      IsReadyConfirmedByITFM

  Models/HallBlock.cs
    Blocks a room for a date range:
      ConferenceRoomId, StartTime, EndTime
      Reason (e.g. "Annual Maintenance")
      CreatedByUserId

  Models/AllocatorHallAssignment.cs  [NEW]
    Many-to-many join table: Allocator <-> ConferenceRoom.
    Fields:
      AllocatorUserId  (FK -> AspNetUsers)
      ConferenceRoomId (FK -> ConferenceRooms)
      AssignedAt       (timestamp of assignment)
      AssignedByUserId (Admin who made the assignment)
    Unique index on (AllocatorUserId, ConferenceRoomId) to
    prevent duplicate assignments.
    One hall can have multiple allocators.
    One allocator can be assigned to multiple halls (only if
    explicitly assigned by Admin).

  Models/AuditLog.cs
    Audit trail for all significant actions:
      UserId, UserName, Action, EntityName, EntityId
      Details, Timestamp

  Models/Enums.cs
    BookingStatus enum:
      Pending, PendingAllocatorReview, Approved,
      Rejected, Cancelled, Completed

  Models/ErrorViewModel.cs
    Error display model for the Error page.

  SECTION 2 - HOW AUTHENTICATION WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

WHAT THE USER SEES ON THE LOGIN PAGE:
  Field 1: Windows Username  (e.g. john.doe - same as their PC login)
  Field 2: Password          (same as their office computer password)

HOW IT WORKS - TWO-STEP PROCESS:

  User enters username + password and clicks Sign In
           |
           v
  [STEP 1] Check LOCAL Identity database
           Covers: sys.admin, sarah.jenkins, marcus.vance, dave.miller
                   and any accounts created via Admin panel
           |
           +---> Password matches? --YES--> User is signed in. DONE.
           |
           +---> Not found / wrong password?
           |
           v
  [STEP 2] Ask CompanyAuthService.ValidateAndGetProfileAsync()
           -> Sends username + password to company server (AD/LDAP)
           -> If valid: receives { FullName, Department, Email }
                        from the company directory
           |
           +---> Company auth failed? --> Show "Invalid credentials"
           |
           +---> Company auth OK?
                 |
                 +---> First time this user logs in?
                       YES -> Auto-create account in local DB:
                                UserName   = windows username
                                FullName   = from company server [automatic]
                                Department = from company server [automatic]
                                Role       = "User" (standard employee)
                       NO  -> Refresh FullName + Department from server
                              (keeps data in sync with company directory)
                 |
                 v
                 User is signed in. DONE.

  SECTION 3 - HOW TO CONNECT TO THE COMPANY SERVER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Open file: Services/CompanyAuthService.cs
Find:      ValidateAndGetProfileAsync() method - the TODO block
Replace:   The "return null" with one of these three options:


OPTION A - WINDOWS ACTIVE DIRECTORY / LDAP [Recommended for NRL]
  1. Install package:
       dotnet add package Novell.Directory.Ldap.NETStandard

  2. Add to appsettings.json:
       "CompanyServer": {
         "LdapHost": "192.168.1.10",    <- your AD server IP
         "LdapPort": 389,
         "BaseDn": "DC=nrl,DC=co,DC=in"
       }

  3. Replace TODO block with:
       var conn = new LdapConnection();
       conn.Connect(host, port);
       conn.Bind(userId + "@nrl.co.in", password);
       var results = conn.Search(baseDn, ...);
       var entry = results.Next();
       return new CompanyUserProfile {
           EmployeeId = userId,
           FullName   = entry.GetAttribute("cn").StringValue,
           Department = entry.GetAttribute("department").StringValue,
           Email      = entry.GetAttribute("mail").StringValue
       };

  The Bind() call throws an exception if credentials are wrong.
  On success, the LDAP entry gives you Full Name, Dept, Email.


OPTION B - COMPANY HR REST API
  Use if your IT team exposes an internal HR portal API endpoint.
  1. No extra package needed.
  2. Add to appsettings.json:
       "CompanyServer": {
         "AuthApiUrl": "https://hrportal.nrl.co.in/api/auth/verify",
         "ApiKey": "YOUR_KEY"
       }
  3. POST credentials to the API, read FullName/Dept from response.


OPTION C - DIRECT HR DATABASE QUERY
  Use if the HR SQL Server/Oracle database is accessible on the LAN.
  1. Add connection string for HR DB in appsettings.json.
  2. Query EMPLOYEE table:
       SELECT FULL_NAME, DEPT_NAME, EMAIL FROM EMPLOYEE
       WHERE EMP_USER_ID = @userId
         AND PASSWORD_HASH = HASHBYTES('SHA2_256', @password)
